# WR 2.0: rebuild with 9 pages and Google Sheets

## Context
The current WR is a single-purpose client tracker. It stores everything on the phone (IndexedDB) and is live at https://mahmudmaatuk-boop.github.io/wr/ (repo `/Users/mini/wr`, vanilla JS, no build step). The user wants a **full rebuild** into a small business app for Wood for Life:

- A **Welcome page** with a big "Welcome", a **Website** button (https://www.woodforlife-wr.com), and **9 pages** in a 3×3 grid of iPhone-style icons.
- Pages: Client info · Monthly expenses · Client info monthly · VAT · Packing & Shipments · WR-Documents · Raw Stockage · Finished Stockage · Backup.
- **Data is stored in Google Sheets in the Woodforlife2019@gmail.com account.** The Backup page writes everything into one organised Google Sheet with a tab per page.
- An iPhone-like UI in **tree colours** (browns, bright brown, greens, light green) that's simple to use.

**User decisions:** a 3×3 icon grid. **Save offline, upload later.** Entries can be **added, edited and deleted** in the app. **Old on-phone clients are moved** to the Client info sheet.

## Architecture (free, no servers to run)
```
iPhone (installable web app on GitHub Pages)
  ├─ pages.js schema → generic forms and lists → outbox (IndexedDB) → api.js
  └─ cache of last downloaded lists (offline viewing)
         │  HTTPS POST (JSON + access key)
         ▼
Google Apps Script web app (runs as Woodforlife2019@gmail.com)
  ├─ Google Sheets: one spreadsheet per page + "WR Backup"
  └─ Google Drive:  WR/Photos, WR/WR-Documents
```
- **Why Apps Script:** it's free, lives inside the Woodforlife Google account, needs no Google Cloud project and no sign-in screen in the app, and can write Sheets and Drive. The app sends `POST` requests with a `text/plain` JSON body, so the browser makes no CORS preflight request.
- **Security:** `setup()` generates an **access key** stored in the script's properties. Every request must carry it, and page names are checked against an allow-list. The **script URL and key are typed once into the app's Settings and stay only on the phone**, never in the public GitHub repo.
- **Schema-driven app:** every page is a config entry in `js/pages.js` (fields, dropdowns, calculations, sheet name, list layout). One generic form and one generic list render all the standard pages. The server is generic too: it maps fields to columns by **header name**, so reordering columns in Sheets doesn't break anything.
- **Record IDs:** each row has an `ID` column (a UUID made on the phone, so offline edits and deletes work before upload). Rows typed by hand in Sheets get an ID the next time the app reads that sheet.
- **Offline outbox:** every save goes to an IndexedDB outbox first, including photos and files. It's sent immediately when online, otherwise when connection returns, on app start, or with *Sync now*. Queued operations are merged: add then edit becomes a single add, and add then delete cancels out. The Welcome page shows *All synced*, *3 waiting to upload*, or *Offline*.
- The v2 app uses a **new local database (`wr2`)**. The old `wr` database is only read, by the one-time import, and is never deleted.

## Pages
All money is USD and handled in cents (no rounding drift). Timestamps are set automatically (time zone **Asia/Beirut**). Each standard page has a segmented control **New | Saved (n)**: *New* is the form with its button at the end, *Saved* is a searchable list. Tap an entry to edit or delete it.

- **Old-client import mapping:** name, phone, email, photos and created date become the Timestamp. Paid becomes Payment status. The old Amount becomes Paid amount. The old wood text is kept as typed. **Delivery status isn't in the new form, so it's not carried over.**

## Google side (`apps-script/Code.gs`, committed to the repo)
- **`setup()`**, run once by the user in the Woodforlife account, and safe to re-run:
  - creates the Drive folder `WR` (subfolders Photos and WR-Documents)
  - creates the spreadsheets **Client info, Monthly expenses, Client info monthly, VAT, Packing & Shipments, WR-Documents, Raw Stockage, Finished Stockage, WR Backup**
  - styles the headers (bold, white on bark brown, frozen, with filters), applies USD and date formats, and adds **real dropdowns** for Wood type, Base and Payment status, so typing directly in Sheets uses them too
  - sets the time zone, generates the access key (printed in the log), and installs the monthly backup trigger
- **Web app API** (`doPost`): `ping`, `list`, `add`, `update`, `delete`, `getFile`, `backup`, `status`. Writes use `LockService`, so two phones saving at once can't clash.
- **Backup:** for each page, the data is copied into its own tab of **WR Backup** (the monthly tabs are merged with a Month column; WR-Documents lists the files and links), with formatting applied. A **Summary** tab shows the backup time, rows per page and key totals. Each backup overwrites the previous one, but **Google Sheets version history keeps every earlier backup** (File → Version history).

## Build order
1. Create the branch and save the spec.
2. **Test-first** for the pure modules: `calc` (VAT, totals, volume, cents, month keys), `pages` and `validate`, `sync` (outbox merging and retries), and `migrate` (old to new mapping).
3. `Code.gs`, with `tests/server.test.js` loading it in a Node `vm` with fakes to cover: a wrong key is rejected, unknown pages are rejected, columns map by header, the month upsert, tab per month, ID assignment, delete, and backup tabs and Summary.
4. The mock server, then `store`, `api` and `sync`, then the form and list components, then the views and CSS.
5. PWA shell, the setup guide and the README.

3. **Google setup:** following `docs/SETUP-GOOGLE.md`, you sign in to Woodforlife2019@gmail.com, paste `Code.gs` at script.google.com, run `setup`, deploy it as a web app, and paste the URL and key into WR's Settings on your phone. **I can't sign in to that account for you; this part takes about 10 minutes.** Then you test on the phone: the entries appear in the Google Sheets and Back up now fills WR Backup.
4. **Go live:** once you've tried it, and with your OK, merge `rebuild` into `main` and push. GitHub Pages updates, and your Home Screen WR becomes v2 (open it, connect it, then Import old clients).
